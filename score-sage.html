⚡ Princeton Review Strategy: The Scope Trap
That "two-answer" moment is by design — the SAT test writers engineer it deliberately. Here's the key: wrong answers on main idea questions always fail the scope test.

They're either too broad (go beyond what the passage says), too specific (focus on just one detail), or too extreme (use words like "always," "never," "proves").

The correct answer matches the passage's scope exactly. Try this: after reading, summarize the passage in 8 words. Then match your summary to the choices.

📝 Practice Question — SAT Reading Read this passage, then answer the question:

"The decline of cursive handwriting in schools has sparked debate among educators. While some argue that typing skills are more practical in the digital age, others contend that cursive develops fine motor skills and activates different cognitive pathways than printing or typing."
Which best states the main idea of this passage?

A) Cursive handwriting should be eliminated from school curricula
B) There is disagreement about whether to continue teaching cursive
C) Typing is more important than handwriting in the modern world
D) Cursive handwriting activates unique cognitive pathways in the brain

Which would you choose — and why?
E
I'm between B and D... I'll go with B.
SS
✅ Correct! Here's the full breakdown B is right — and here's how the scope test proves it every time:

• A is too extreme — "should be eliminated" is never stated, just debated
• C is too specific — only one side of the debate, not the whole passage
• D is too specific — one detail mentioned, not the central point
• B ✓ — the entire passage is about the debate itself, and B captures that exactly

You hesitated at B vs. D — that tells me you're already applying scope thinking instinctively. D is tempting because it sounds substantive, but the SAT rewards answers that match the whole passage, not the most interesting sentence in it.

How we'd build it

Score Sage is a Next.js RAG application deployed on Vercel — purpose-built for fast iteration and a serverless-first architecture. Here's the full stack and a 6-week path from zero to beta.

Tech stack
Frontend + API
Next.js 14
App Router · TypeScript · Tailwind
SSR for fast initial load. API routes co-located with the frontend. Zero-config Vercel deployment on every push.
Language model
GPT-4o
Primary LLM · Claude Sonnet fallback
Best-in-class instruction following for Princeton Review strategy coaching. Multi-provider routing via Vercel AI SDK for resilience.
Vector DB / RAG
Pinecone
Serverless · OpenAI embeddings
Princeton Review book content chunked by strategy, embedded with text-embedding-3-small, and retrieved at query time. Filtered by test type.
Database
PostgreSQL
Neon or Supabase · serverless pooling
User accounts, session history, mastery state, subscription status. Relational schema chosen for complex mastery queries.

Streaming
Vercel AI SDK
useChat hook · Server-Sent Events
Handles token-by-token streaming from GPT-4o to the browser with minimal boilerplate. Essential for the live-tutor feel.

+ Sentry + LangSmith
Preview URLs on every PR. Edge functions for streaming. LangSmith traces every LLM call for quality evaluation and cost monitoring.
How the AI works — RAG request flow
1
Student sends a message
Client POSTs to /api/chat. API route validates the session, checks rate limits, and fetches the student's context — test type, current score, goal score, mastery state summary.
2
Embed the query
The student's message is embedded using OpenAI text-embedding-3-small (1536-dim vectors). This turns the question into a semantic fingerprint for retrieval.
text-embedding-3-small
3
Retrieve Princeton Review content
Pinecone vector search finds the top-8 most relevant Princeton Review content chunks — filtered by the student's test type. Top-4 are injected into the prompt context. Each chunk is tagged with strategy name, topic, and question type metadata.
Pinecone semantic search
4
Assemble the system prompt
Four layers are stacked: (1) Princeton Review persona and voice, (2) test-specific strategy rules for the student's selected exam, (3) the retrieved content chunks, (4) the student's current context — score, goal, mastery gaps, session count.
5
Stream the response
GPT-4o generates a response with streaming enabled. Tokens flow back to the browser via Server-Sent Events through the Vercel AI SDK's useChat hook — producing the live-tutor typing effect.
GPT-4o · streaming SSE
6
Update mastery + persist history
On stream completion, strategy tags and mastery deltas are extracted from the response metadata and written to PostgreSQL. The conversation turn is appended to the session history. The mastery sidebar updates in real time.
PostgreSQL · real-time mastery update
